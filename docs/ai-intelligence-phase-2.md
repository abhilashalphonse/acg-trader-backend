# Phase 2 — Intelligence & Quality Engine

## Product contract

All supported capabilities remain available without a mandatory subscription. Compute will be funded by the user's API allowance or prepaid credits (Phase 3). No model provider or AI inference is introduced here. Phase 1 authorization, financial safety, governance, and default-off activation are unchanged. The system does not establish a profitable edge merely by calculating market features.

## Phase 2A: offline evidence and deterministic facts

The existing backend uses MarketHistoryService, canonical UTC history for D1/W1, a candle engine with complete/synthetic/source/provider fields, QuoteStore, instrument schedules, and a shared decimal implementation. Reuse these contracts, not screenshot inference or a second market feed. The market history path can perform provider fetches and local fallback; future integration must explicitly resolve identity, freshness and entitlement before consuming it.

New pure modules under src/modules/ai/intelligence:
- candle-evidence: bounded 256-bar strictly chronological input with exact symbol/timeframe, explicit closure/synthetic state, valid OHLC, known source/provider labels, as-of timestamp and hash. Exclude synthetic and incomplete bars, fail on malformed eligible bars. Segment at missing intervals and provider transitions. No invented data or implicit bridging. Historical session gaps are not classified as valid closures in this increment. A recent closed candle is not a fresh executable quote. Provenance labels and content hashes are not proof of authentic origin.
- market-facts: last closed price, range high/low on the final contiguous segment, 20-close SMA, simple mean true range over 14 periods (not Wilder ATR), latest confirmed strict two-left/two-right high/low pivots, latest strict three-bar wick gap geometry. Arithmetic uses existing decimal helpers; averaging rounded to 12 decimal places. Pivots only confirmed after right-hand bars close. Gap direction is geometry, not mitigation, institutional activity, entry quality or a forecast. No liquidity sweep, BOS/MSS, strategy recommendation or backtested edge yet.
- fact-verifier: recompute from the same trusted server input and accept only exact typed evidence/fact/value references. Reject unknown, altered, duplicated or cross-snapshot claims. Returned facts include original deterministic metadata. It does not verify natural language, subjective interpretation, forecasts, or omitted context. No cryptographic signature, database record, network access, public route, provider, tool registry changes or execution permission.

The input is internal trusted-server data, not a model-supplied envelope. Must not expose these functions directly via HTTP/MCP. Snapshot IDs include the as-of timestamp; reuse a pinned immutable input when comparing claims, and use a separate freshness check at presentation time. The module is not yet connected to market runtime; schedule and complete coverage validation, data licensing, and quote freshness remain unresolved. This conservative version deliberately stops indicators at any gap, even a legitimate market closure. Initial methodology and thresholds are proposed engineering defaults subject to review and benchmark.

## Phase 2B increment — internal context assembly

- Internal read-only source uses the runtime symbol universe, instrument registry and quote cache, plus majority primary reads of projected Instrument and Candle documents with 1.5 s Mongo query limits. No historyService hydration, provider requests, subscriptions, or writes. Persisted history may be sparse or unavailable; do not manufacture coverage. Source adapter is not mounted or constructed by production runtime.
- One canonical symbol, at most three distinct supported timeframes and 128 bars per timeframe. Exact tenant/actor/session/account tuple; mandatory server authorization callback before data access and before disclosure. No permissive default. Actual Phase 1 grant/governance and provider licensing/entitlement binding is NOT implemented; there is no active caller. No account balances, positions, drawings, messages, credentials or external tool output are read.
- Configured schedule coverage uses existing session-calendar and scheduleHash, validates explicit schedules, holidays/overrides and UTC bucket alignment, and distinguishes missing open buckets from expected closed gaps within the observed range through as-of. At most 4096 minute probes per series. Other provider bucket contracts, invalid/missing schedules and exhausted budget return UNKNOWN. Calendar matches are not independent venue verification or completeness within each bar. Facts are suppressed when known out-of-session bars exist; the Phase 2A conservative contiguous segment remains unchanged across gaps.
- Cached quotes require exact provider mapping/source, positive ordered bid/ask, both receipt and provider timestamps, non-stale flag, age within instrument hard threshold, explicit synthetic-spread flag, and configured session open at provider and assembly time. REST recovery without provider timestamp is not treated as live. Quotes are descriptive and NEVER executable; timestamp/mapping labels do not prove provider identity.
- Snapshot has explicit as-of, completion and 10-second expiration, content hash, immutable output and source recheck. Separate quote expiration. Caller must recheck expiry/permissions at presentation. Not a transaction across timeframes; no historical replay correctness for provider revisions, no persistence/retention yet. Identity attestations, actual entitlement binding, account/workspace context, multi-symbol context, historical point-in-time source, schedule validation against exchanges, distributed load testing, integration and evaluation remain outstanding. Limits are initial conservative design assumptions.


## Phase 2C — advanced market intelligence (methodology v1)

The first version is a deterministic descriptive feature library, not an approved trading strategy or proof of actual liquidity. It uses only Phase 2A validated closed bars in the last uninterrupted same-provider segment. No signal bridges a missing/synthetic bar or known provider change. References and events carry confirmation times; IDs derive from versioned inputs. Outputs retain the last 32 pivots, equal levels, events and zones per series plus totals, with full bounded-window state calculated internally.

- Liquidity references: strict two-left/two-right confirmed swing highs/lows; exact equal consecutive same-side confirmed swing levels are potential liquidity references. No tick-tolerance clustering, volume/order-book proof, or inference of resting institutional orders. The latest confirmed reference per side is tracked; newer references replace it.
- Sweep proxy: a candle opens on/inside the reference, trades strictly beyond it and closes strictly back inside. One sweep per reference; a sweep does not prevent a later close break. No intrabar event order or execution claim.
- Structure: a close crosses a previously confirmed swing (previous close on/inside, current close strictly beyond). First break establishes descriptive bias; continuation is BOS, opposite break is MSS_PROXY, not a fully validated ICT MSS/displacement setup. Opening gaps are explicitly flagged. A pivot is available only after its second right candle closes, and can be acted on by later candles only. Ties do not form strict pivots.
- FVG: strict three-closed-bar outer wick separation; formation at third close. Track subsequent range intersection, near-edge touch, partial observed depth, distal touch and close beyond distal invalidation. Gap-through without observed intersection is distinct. Distal touch does not prove a traded-through or fully filled zone; no order flow/mitigation causality claim. Stop tracking after first invalidation.
- Session analysis: caller-supplied explicit UTC window aligned to intraday buckets, maximum 24 hours and 256 expected buckets. Report observed OHLC/range, elapsed bucket count, missing buckets, window ended/in-progress, and mixed-provider abstention. No hardcoded London/Asia/New York hours, DST conversion, or verified exchange-session meaning. Historical/closed-session gaps within an explicit window count as missing elapsed buckets; the range is qualified accordingly.
- Multi-timeframe structure: same symbol/as-of and matching evidence IDs, recent closed bar, configured-calendar coverage match and established break direction required per timeframe. At least two qualified frames; otherwise abstain. Aligned or mixed historical breaks are not predictive trend or confluence probabilities.
- Internal assembler now attaches versioned structure, cross-timeframe summary and up to three explicit session windows, included in authorization request. Known out-of-session evidence suppresses structure and session reports. The existing Phase 2A numeric fact verifier remains limited to its original typed facts: structured advanced features will require independent recomputation and claim verification in 2E. No public tools or new authorization grants.

Acceptance: synthetic causal prefix replay, swing confirmation, sweep/close-break ordering, continuation and reversal proxy, exact equal levels, bullish/bearish gap depth, gap-through, missing/synthetic bars, explicit session ranges and multi-timeframe abstention. These are provisional engineering definitions; independent labelled real-market evaluation, session/DST methodology, displacement, liquidity tolerance, source entitlements, full historical point-in-time data, and Phase 1 authorization integration remain gates. No inference, production changes or activation.


## Phase 2D — knowledge and prompt engine

- Versioned original internal ACG methodology catalog: eight entries (evidence, financial boundary, structure, liquidity, FVG, session range, multi-timeframe and indicators). Every entry has an immutable versioned content ID, method version, origin, ENGINEERING_DRAFT review status and INTERNAL_ONLY distribution. Four explicit server-selected profiles (MARKET_OVERVIEW, STRUCTURE, SESSION, EDUCATION); evidence and financial boundary are mandatory in every profile. No external document ingestion, vector retrieval, automated internet retrieval, or third-party strategy text.
- Provider-neutral prompt package keeps immutable server-owned policy/response contract separate from user question, knowledge and projected evidence. No role interpolation, tool declarations, execution permissions, provider calls, network or runtime registration. A future adapter must map these channels to actual provider-native roles and structured response features; this code does not enforce a model's behavior.
- Requires exact expected tenant/actor/session/account scope and an unexpired assembled context for market profiles; education can explicitly run without market evidence. Checks context hash, source evidence IDs, scope, as-of and expiry. Hash is an integrity check, not proof of origin or authorization. Trusted server only, after fresh authorization; never accept model/client-supplied context or scope as trusted.
- Projects existing typed facts, active liquidity references, recent equal levels/events/zones, session ranges and cross-timeframe summary into deterministic unique reference IDs. Omits raw candles and scope identifiers from the projected market payload; preserves quality, method limits, totals and selection counts. Quote observations expire independently; expired quote values are excluded. The package expiration is no later than the earliest included quote/context expiration. Reauthorize and recheck expiry before inference and presentation.
- Initial limits: user question 4096 UTF-8 bytes; total serialized payload 49152 bytes, fail closed rather than silently truncating arbitrary content. Per series recent selections: four equal levels, six events, four FVG zones. Byte size is not provider token count or cost. Provider-specific tokenizer/budget and semantic relevance retrieval deferred. User question stays intact as untrusted data and may itself contain personal information/secrets; no claim of DLP or safe external transfer. All knowledge currently INTERNAL_ONLY; distribution/consent and market licensing require explicit approval before external provider use.
- Response contract is a descriptive candidate schema: reference-only observations, qualified interpretations and educational explanations with knowledge IDs, explicit insufficiency and limitations. Not a runtime JSON schema validator or verification of arbitrary prose. Phase 2E will enforce strict schemas, independent recomputation, evidence/reference matching, freshness, unsupported claim rejection and deterministic presentation of verified facts. No raw candidate response should be exposed as verified.

Acceptance fixtures cover stable knowledge and package IDs, mandatory boundary knowledge, role-injection text separation, real assembled context projection, scope mismatch, modified/expired context, independently expired quote, unsupported profiles, byte bounds and educational mode. These tests demonstrate deterministic packaging, not resistance of a live model to prompt injection. Model-level adversarial evaluation, DLP, reviewed knowledge, external source permissions, retrieval/memory and Phase 1 integration are still outstanding. AI activation stays blocked.


## Phase 2E — verification and response engine

- Context assembly pins projected input candles, instrument schedule/mapping and cached quote in a process-local WeakMap keyed by the actual immutable server-minted context. Only trusted internal code can obtain replay material; nothing new is serialized to model payloads. A cloned or model-provided context is not accepted by the response engine. No durable replay store, cross-worker transfer or authenticated distributed ticket mechanism yet.
- Prompt contract v2 supersedes v1: strict JSON candidate with status, observation reference IDs, interpretation reference IDs and approved code, and education knowledge IDs. No arbitrary model prose, numerical fields, tool calls, or claimed confidence. Interpretations resolve to fixed server text tied to the correct reference type. Educational answers use original versioned catalog entries. This deliberate restricted pilot is not a general natural-language assistant. Future expansion requires independently validated claims and explicit nonverified interpretation handling.
- Prepare requires matching scope and server authorization callback, creates a process-local opaque single-use ticket bound to exact scope, context, question and profile. Verification consumes a matching ticket before asynchronous work; foreign, duplicate or serialized tickets cannot disclose results. Verify requires authorization again before work and just before disclosure. Expiration of any included quote expires the entire package; current 10-second context TTL may be too short for actual provider inference. No live model integration; calibrate with benchmarks and separate historical vs live validity before use.
- Strict Zod parser for candidate JSON (16 KiB max, bounded arrays, no unknown fields). Reject unknown market or knowledge references, duplicate IDs, mismatched interpretation codes, contradictory empty answer or evidence-bearing abstention, and arbitrary text. A rejected candidate returns a fixed error code and null response, never echoes raw output.
- Independently rerun existing Phase 2A/2C calculations, coverage, session windows, quote qualification and cross-timeframe comparison from pinned raw inputs; compare reconstructed results to original assembled context. Recompile original prompt at original clock and compare entire package. Then select only server-owned typed facts and fixed educational/interpretation material. The model cannot supply prices, structure levels or free-text statements for rendering. Context quality and limitations accompany the response. This is a recomputation consistency check using the SAME deterministic methods, not independent algorithm validation or provider identity proof.
- Verified means reference selection and reproducibility only. It does not establish semantic relevance, completeness, correctness of the underlying data/algorithm, predictive edge, or correctness of arbitrary text. No account risk calculation, live trade preparation or execution. Current Phase 1 authorization callback remains unbound to production session/grant/governance/data licensing; no runtime caller. Recheck actual permission and freshness at presentation. No persistent audit integration for this unmounted engine yet.
- Acceptance fixtures cover actual assembled replay, source mutation after snapshot, typed market/knowledge selections, fabricated values and extra text, unknown and duplicate references, cross-account/one-use ticket, simultaneous duplicate responses, expiry and late revocation, educational mode and abstention. Real labelled data evaluation and adversarial live provider evaluation are later gates. AI activation remains blocked.
