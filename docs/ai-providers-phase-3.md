# Phase 3 — AI providers and compute credits

## Product invariant
Every supported capability is available to eligible users without mandatory subscription tiers. Compute is funded explicitly via BYO_API (including any provider allowance) or ACG_CREDITS; no silent switching, auto-topup or fallback. Account authorization, market-data licensing, provider compatibility and independent financial controls still apply. No live activation in this phase without separate acceptance and approval.

## 3A — provider interface and model capability registry
- Six planned integration targets: OpenAI, Anthropic, Gemini, DeepSeek, OpenRouter, custom endpoint. These are identifiers, not live availability or capability claims. All are disabled. Default model catalog empty. No provider SDK, endpoint, external network, API credential, billing, account write, HTTP route or runtime registration.
- Trusted-server immutable descriptors identify provider/model/revision and versioned descriptor hash, supported funding modes, text input, JSON schema/object output capability, instruction channel separation, streaming support, usage reporting and token bounds. Only explicitly enabled synthetic fixtures can resolve in offline test mode; all runtime resolution fails closed unconditionally. Production registry review and model-specific compatibility tests are future gates. Model IDs/limits/prices are not guessed.
- Universal offline request envelope pins model descriptor, one funding mode, unique request ID, Phase 2 prompt ID, timestamps and budget. Checks package hash, byte length, version and expiry. Preserves policy and data in distinct channels; no tool declarations, credentials, endpoint or account identifiers in request projection. Funding metadata stays outside the provider request. The question can itself contain secrets; no claim of DLP or permission to export. Hash is not origin proof. Inputs are trusted-server objects only. Planning token upper bound is an asserted estimate, not measured or billable usage. Real tokenization and provider-specific schema support remain gates.
- JSON schema describes Phase 2 candidate-response-v2; no execution tools or free-form output accepted for verified display. The existing Phase 2 verifier retains independent responsibility for strict candidate validation, evidence replay, authorization and freshness. The normalized candidate is never a verified answer.
- Future adapter interface: one-shot async generate(request) returns normalized outcome. Concrete fixture adapter uses fixed offline data only. Real provider transport, cancellation, streaming, deadlines, authentication, idempotency, usage mapping, safe error classification and external data authorization deferred. No automatic retry/fallback or settlement. Outcome must match request, model and descriptor. Non-completed results suppress text; errors use fixed categories. Unknown usage explicitly distinct from zero. Reported input/output are inclusive totals; optional cached input and reasoning output are subsets, never added again. Provider-specific billing dimensions outside this schema (e.g. cache writes, separate reasoning, modality or request fees) must be mapped and priced explicitly before accepting real usage. Preserve overrun usage for reconciliation, not silent clipping or automatic debit.
- Tests use invented model fixtures and the actual Phase 2 education verification pipeline. No live inference. Existing Phase 1/2 release regression remains mandatory.

## Subsequent stages
3B credential vault: per-user ownership, envelope encryption/key rotation, write-only secret interfaces, scoped revocation and audit; no logs or model exposure. 3C provider adapters: fixed allowlisted destinations, provider-native role/schema mapping, safe normalized transport and bounded streaming; custom endpoint SSRF controls and provider-specific acceptance. 3D orchestration: explicit funding/selection, cancellation/deadlines, idempotency and no silent fallback. 3E usage and pricing: versioned exact billing dimensions, currency/rounding, provider-reported vs unknown usage, rate snapshots, reconciliation. 3F transactional ledger: integer monetary units, reservations, settlement, release, duplicate/unknown outcomes, concurrency and durable audit. 3G purchases/payment reconciliation: verified signed webhooks, idempotency, refunds/chargebacks, payment/legal review. 3H budgets and optimisation: account limits, no unauthorized credits, cache isolation, token control. 3I Phase 1/2 integration: actual data entitlements, reviewed knowledge, consent/DLP, freshness policies (10-second context TTL is not suitable for general inference), independent response validation. 3J acceptance: adversarial provider, financial ledger, outage, load, actual model and usage tests; licensed real-market evaluation and permission requirements remain. 3K isolated staging and disabled production release.


## 3B — encrypted credential vault and connection management
3A acceptance: Backend CI 45805158010 and Paired release acceptance 45805158187 passed at 3e9269d07866b556ca502f89cba2e28f680aae5a.

- One BYO API connection slot per tenant + global user + supported direct/aggregator provider. Same person in different tenants has separate credentials. Session identity is checked on every operation but is not the durable owner. Custom endpoints excluded until destination validation and SSRF/egress controls. No ACG-managed provider credentials or credit funding stored in user vault. No API key validity/network check yet; status STORED_UNVERIFIED never means connected/live. No user-supplied URLs, model payloads or tool invocation.
- Authenticated AES-256-GCM envelope encryption: independent random 256-bit DEK per replacement, random 96-bit IV per encryption, 128-bit tag, wrapped by injected 256-bit KEK. Associated data binds tenant, actor, provider, connection ID, generation, format/purpose and wrapping key ID where applicable. Rewrap authenticates old wrapped key and encrypted credential, then wraps the same DEK with active KEK; no provider access. Tampering or wrong/missing key fails closed. No default master key or environment loading; no production KMS integration. Keyring injected into trusted server process, supports current + previous KEKs, explicit version and rotation. Temporary buffers zeroed best-effort; JS strings, runtime memory and backups cannot be reliably erased. Crypto module has an internal decryption primitive for tests/future trusted worker; service exposes only metadata and write operations. No public read/decrypt endpoint, no runtime credential lease. Future dedicated worker must enforce current generation/authorization before each request and prevent secret exfiltration. No claim of process isolation or external key custody.
- Explicit CONNECT (revision 0), REPLACE, REVOKE, RECONNECT and REWRAP operations with expected revision; revoked tombstone cannot be silently replaced. New generation on connect/replace/reconnect; rewrap does not change credential generation. Revoke clears active envelope and records revision; cannot revoke provider-side key or undo already dispatched requests, and encrypted copies may remain in DB history/backups. User must revoke provider key at provider if needed. API key accepted as bounded printable ASCII, never returned or included in authorization request or audit. No API key format guessing. Connection metadata is read-only, not a health assertion. One slot per provider is a first-pilot design choice, not an entitlement limit.
- Mandatory action-specific authorization callback, before read, before write and before response. No permissive default. Current authentication/ownership exercised in CI with actual Supabase session fixtures; production Phase 1 binding, governance and revoke exception policy still required. A late denial may occur after transaction commit; suppress disclosure and reconcile via metadata read. No blind retry. Production raw request logging/redaction, rate limit, request body bounds, step-up auth and audit of denied attempts are later activation gates.
- New Mongo models autoCreate/autoIndex false, scoped primary/majority projected reads, unique owner/provider index, CAS and append-only application audit event in a replica-set snapshot/majority transaction. Audit includes operation, owner/session, connection, revision, timestamp only; no credential/ciphertext/prompt. Direct DB access is not tamper-proof. Explicit schema/index provisioning before enabling any caller; no production migration. No financial mutations. Store catches raw driver/validation errors and emits fixed codes; uncertain commit needs reconciliation. Revocation is explicit, not triggered by provider failure.
- Isolated acceptance: encryption randomness, AAD transplant rejection, tampering both envelope layers, rewrap under new key, metadata-only disclosure, owner isolation, bounded inputs, pre/late denial, concurrency. Actual random loopback Mongo test uses real sessions, indexes, concurrent creation/replacement, rewrap, forced audit rollback, revoke/reconnect and audit immutability; default-off HTTP check asserts no provider/credential routes even when Phase 1 flag on. No network, real keys, provider inference or user billing.
- Release gates: actual provider-specific adapters, independent data consent/licensing, secure KMS/secret injection and rotation procedure, operational logging/privacy review, dedicated credential consumer authorization, durable audit retention and failure reconciliation. Never activate from this PR. Fresh CI required.


## 3C — provider wire adapters and normalized streaming
3B acceptance: Backend CI 45805866763 and Paired release acceptance 45805868936 passed at aae2045a207656579d3a3bd41649008a0f56ccf3.

- Five fixed destination wire mappings: OpenAI, DeepSeek and OpenRouter Chat Completions; Anthropic Messages; Gemini generateContent/streamGenerateContent. Request method POST, fixed HTTPS destinations, redirect error policy, credential scheme descriptor only (no authorization header or secret), separate system/user data, no tools, explicit output cap. Structured schema mode only where descriptor and mapping permit it; DeepSeek restricted to JSON object mode. OpenAI store false and OpenRouter allow_fallbacks false/require_parameters true requested; these are request parameters, not verified upstream retention or routing guarantees. Custom endpoint excluded. Model catalog remains empty and runtime resolution unconditionally blocked. Wire builder does not send HTTP, resolve DNS, decrypt credentials or invoke SDKs. Live transport, provider route pinning, actual model capability/limits and authentication acceptance remain prerequisites.
- Offline request explicitly gates streaming on model capability. Reader accepts injected byte chunks, supports fragmented UTF-8, SSE CR/LF/CRLF, data lines, event names and keepalive comments; strict JSON parsing. Limits: 256 KiB wire body, 32 KiB SSE event/line, 1024 data events, 4096 chunks, 16 KiB candidate, overall deadline capped at 30 seconds and prompt expiry. Cancellation races iterator reads, cleans up timer/listener, attempts iterator return without blocking; cannot guarantee actual upstream cancellation or prevent provider billing. No incremental unverified text disclosure. A completed candidate is still UNVERIFIED and must pass Phase 2 verifier. Production streaming UI can show progress only until verification. Actual streaming transport and cancellation handling remain deferred.
- Chat protocols require finish_reason and [DONE] for SSE, strict single candidate and exact model match, optional final usage; Anthropic requires message start, text block lifecycle, final stop reason and message stop; Gemini requires explicit finish reason and clean SSE EOF, modelVersion checked when supplied (alias/version acceptance deferred). No tool output, arbitrary nontext blocks, unknown terminal reasons or post-terminal events accepted as verified candidate. Reasoning fields not surfaced; unsupported content and malformed streams fail closed. Missing/invalid/uncertain usage is UNKNOWN, not zero. Chat cached/reasoning counts are subsets of inclusive prompt/completion tokens; DeepSeek checks cache hit/miss sums when present; Anthropic adds cache reads and writes to input and uses final cumulative output (not sum of deltas); Gemini adds thoughts to candidate count and checks reported total. Cache-write, provider-specific fees, routing, exact billing dimensions and partial usage reconciliation remain 3E/3F gates; no automatic debit. Timeout/cancellation/transport failure suppresses candidate and may leave unknown usage. No fallback or retry.
- Tests use five synthetic protocol fixtures for both complete JSON and incremental SSE, byte fragmentation including multibyte text, no tool authority, truncation, refusal, HTTP classifications, model mismatch, malformed UTF-8, output/stream bounds, deadline/cancellation, missing/inconsistent usage and actual Phase 2 candidate verification. No live provider claim or price assertion. Current 10s context expiry still limits inference; separate historical/live freshness and actual data authorization required.

Model-specific compatibility must be tested before activation. Fresh integrated CI required.
