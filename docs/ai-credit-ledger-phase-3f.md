## Scope and invariants
- Synthetic, isolated CI only. Store and service refuse initialization outside NODE_ENV=test, ACG_AI_ISOLATED_CI=true, connected 127.0.0.1 and random acg_ai_ci database. No production collections provisioned. No real funding, payment, network dispatch, runtime endpoint, price schedule or credit sale. Test fixture funding is not a production mint API.
- One wallet per tenant/user (not trading account balance); owner-wide idempotency binds original session/account for request access. Exact unsigned pico-USD integer strings (24 digits max), BigInt arithmetic, balance invariant credited = available + reserved + spent, no negative buckets. No floating point, withdrawals, transfers, refunds, credit expiry, fees or real payment logic.
- Persist wallet, reservations and append-only application journal. Unique owner/provider request identity via owner/idempotency and globally unique requestId, unique journal wallet revision. Majority snapshot replica-set transactions with CAS on revisions; wallet/reservation/journal move together. No mutable balance-only accounting, no TTL deletion of unresolved holds or idempotency tombstones. Direct database access is not tamper-proof; production least-privilege credentials, retention and journal reconstruction/reconciliation remain gates.
- Synthetic credit grant reference globally unique, identical replay returns current wallet; changed amount/owner cannot mint again. CAS protects concurrent admissions. Store hides raw errors, unknown transaction outcome must be reconciled before retry; an authorization failure after commit suppresses response, not proof of rollback.
- Reserve only ACG_CREDITS; validate Phase 3E pinned snapshot and recompute upper bound. Persist request metadata and immutable price JSON, not prompt, context, key or model response. Reject insufficient available credit. RESERVED -> DISPATCHED is a one-shot transactional claim; only the successful claimant receives an attempt ID and dispatch permission. Duplicate/restarted/uncertain claim does not dispatch. No automatic retries or fallback.
- SETTLE only on trusted definitive normalized usage and matching request/attempt, recalculating cost from persisted rate snapshot. Atomically deduct actual cost from reserved and release remainder. Identical settlement is idempotent; contradictory evidence conflicts. Missing/unknown/overrun usage, CANCELLED or ambiguous outcome retain entire hold and enter RECONCILIATION_REQUIRED. Reconciliation may settle later with matching definitive evidence. Release only RESERVED and never claimed; expiry recovery releases undispatched holds, quarantines dispatched holds. No automatic refund after dispatch, no arbitrary write-off/manual override, no automatic recovery scan yet. A claim committed before a crash or late permission denial may leave a conservative hold even if no provider was actually contacted.
- Optional isolated ledger integration in existing offline orchestrator: reserve then claim before synthetic managed inference, recheck authorization, settle before response verification, BYO bypasses wallet entirely. A new orchestrator instance with the same durable idempotency key cannot redispatch even if process-local record was lost. Current restart replay returns conservative error/receipt lookup needed, not prior answer. Existing fixture-only no-ledger simulation remains for regression tests; no production dispatcher exists. Real distributed concurrency, durable request fingerprint and orchestration for BYO, provider request identifiers/invoice evidence, crash/failover and worker recovery policies are still required.
- Tests require real Mongo rs0: concurrent balance admission, single dispatch claim, duplicate settlement, overrun and unknown holds, isolated new service recovery, exact balances, rollback after journal failure, unique references, owner isolation, BYO bypass and actual offline orchestration with Phase 2 verifier. Fixtures use current Supabase session auth callback, not production financial authorization. No real credits, payments or production changes.
