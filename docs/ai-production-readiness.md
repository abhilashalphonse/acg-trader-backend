## Implemented, unmounted
- LiveAdmission: majority-committed replica-set transactions, tenant and actor UTC-day request/cost reservations, durable per-message operation ID, explicit chart consent pinned to session/account/connection/model/policy/symbol/timeframe and control revision, independent market entitlement at grant/claim/dispatch/disclosure, atomic conflict with control/consent revocation, receipt reconciliation. Unknown outcomes retain the original reservation; only CLAIMED can be abandoned without provider use. No refunds or retries on ambiguous dispatch. Amounts are integer pico-USD. Rates are server-approved per token, not client inputs. This is an admission ledger, not a credit wallet or provider invoice.
- Request-bound session authority reauthenticates using existing trader session, account grant and AI governance. A trusted market export policy is still required. Admin and reconciliation authorization must be composed with verified roles and invoice evidence; test callbacks are synthetic only.
- Live runtime configuration: default off, pinned fixed OpenAI endpoint, descriptor digest, explicit release approval, no streaming or provider storage, required secret custody port. Does not dispatch or read key values. The synthetic test descriptor is not approved for live use.
- Separate durable pause revision invalidates old consents and blocks new claims/dispatch. Already transmitted requests cannot be recalled; suppress disclosure after revocation and retain unresolved usage. The check immediately before network write and the check before UI disclosure are still required in the actual adapter.
- Isolated real Mongo acceptance is included in existing GitHub Actions suite; no new Railway resources, production writes, public network inference or provider spend.

## Release blockers
1. Wire unmounted admission into the native conversation runtime and implement actual server-owned market entitlement, verified admin/service roles and explicit export-consent UI, including revoke during dispatch, scope change and browser recovery. Do not treat UI abort alone as revocation. Require reauthentication and independent authorization for all actions.
2. Review actual provider descriptor/price, secure secret storage and rotation, bounded direct TLS egress, exact request budget, DLP and retention, market-data export rights and trusted provider reconciliation. The one-shot smoke approval was consumed; no additional billable request is authorized.
3. Reconcile actual provider usage/billing from independently authenticated evidence, address unresolved token discrepancy from smoke. Tenant/actor UTC-day counters are not a platform-wide budget; add platform-wide spending policy, rate/concurrency limits, outstanding unknown exposure cap and cross-day monitoring before a multi-tenant pilot. Preserve historical ledger holds and use explicit correction workflows for provider usage outside reservation.
4. Perform actual production-like isolated staging deployment with synthetic no-egress transport and real session/role/entitlement composition, concurrency/load/fault tests, DB backup/restore, and rollback rehearsal. CI replica-set tests are a prerequisite, not Railway staging acceptance.
5. Before activation: separate approval of cost cap, audience and data policy; one approved synthetic live canary; restricted staff-only read-only pilot. On incident: disable provider admission, revoke consents, suppress pending disclosure, preserve usage and audit records, keep trading paths independent. No auto-retry of unknown outcomes. Verify no public AI route is accessible when disabled.
