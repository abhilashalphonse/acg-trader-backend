# Phase 4C — Conversation lifecycle (isolated)

Accepted Phase 4B baseline 111aef3b6fe93331a93745bf99360e57f6a55750, Backend CI 45922191496 and paired 45922191498. This increment remains in draft PR #110, with no production app mount.

## Contract
POST /v1/ai/chat/conversations/{create,list,history,append,cancel,delete}, on isolated loopback test listener only. Exact accountId + connectionId authority on every request, real current session and native account grant, tenant governance and persisted quota; separate synthetic purpose approval. No client-supplied tenant/actor/session, roles or assistant answers. Create pins reviewed synthetic BYO education selection and descriptor. List/history reauthorize stored selection; append revalidates descriptor and purpose. Cancel/delete require current grant and distinct operation purpose but not model availability. Reauthentication and authorization before disclosure. History additionally fences on bucket generation/revision and expiry; a final network-delivery race remains possible.

One bounded Mongo document per tenant/actor/account, owner-derived primary key and unique scope index. Majority reads/writes, optimistic compare-and-swap with generation and revision, bounded retries, no network actions inside mutation. New service instance reads durable history, not a queue; no worker exists. Client UUIDs are idempotency keys per owner/conversation; exact append replay returns current receipt, conflicting text rejects; create replay returns current metadata. Sequence is atomic, immutable and contiguous. Cancel changes STORED_OFFLINE to CANCELLED; retry cannot reactivate it. All receipts prohibit dispatch and charges. Only USER text is stored; no fabricated assistant response. History uses sequence keyset pages up to eight messages.

## Retention and safety
Rehearsal limits (not commercial limits): eight conversation slots per account owner including tombstones, 16 messages per conversation, 4096 UTF-8 bytes per text, fixed 24-hour logical expiry from creation. Existing read routes retain 512-character guard; isolated conversation route allows 4096-character strings plus exact schema/byte validation, original 8KB uncompressed body/depth/key restrictions remain. Obvious-secret filter only, not comprehensive DLP; no prompt/response in governance audit. Explicit delete removes text and selection from primary document and retains a minimal tombstone until original expiry to reject replay. Cancel retains user text. Expired conversations are excluded from reads and pruned on successful writes. Mongo TTL is on whole owner bucket at latest expiry, so physical removal of earlier expired content can lag (up to another 24h in normal clock conditions, plus TTL monitor delay); not immediate per-record physical erasure. No backup erasure guarantee. Same UUID may be reused after expiry. No cross-account aggregate cap, no distributed clock rollback protection, no application-level conversation encryption or production retention worker yet. No account values or credentials accepted intentionally; raw user text is persisted only in disposable test database. Production storage consent, encryption/key management, deletion/backup policy, DLP and lifetime/idempotency requirements must be approved before activation.

## Acceptance
Real isolated Mongo concurrency and HTTP integration: exact duplicate create/append, conflicting replay, 16 ordered messages, capacity, UTF8 and obvious-secret rejection, owner/tenant/account isolation, new service instance recovery, cancellation, paginated history, delete racing final history disclosure, tombstone scrub, logical expiry/prune and TTL index. Cross-session storage continuity is exercised via trusted internal scope; a second real login remains a later integrated test. Existing financial/trading/provider tests and default-off real app path checks remain mandatory. No assistant messages, streaming, inference, billing or trade execution in this stage. Frontend history wiring follows 4D and integrated acceptance.
